# ADR-001: Financial System Hardening and Idempotency Upgrades

## Status
Proposed

## Context
Our current financial services (`master-production-orchestrator.js`, `real-web3-executor.js`) lack essential production-grade safeguards:
1. **Idempotency:** Bank settlements via Stripe can potentially double-pay if the orchestrator restarts during a transaction.
2. **Circuit Breakers:** Financial operations continue even when external API error rates (Stripe, Arbitrum RPC) are abnormally high.
3. **Environment Security:** Sensitive credentials like `PRIVATE_KEY` are read directly from `.env` and loaded in memory for the lifecycle of the process.

## Proposed Changes
1. **Orchestrator (`master-production-orchestrator.js`):**
   - Add `idempotencyKey` (generated per sale event) to `stripe.payouts.create`.
   - Implement a simple circuit breaker for bank settlement (disable if 3 consecutive failures).
2. **Web3 Executor (`real-web3-executor.js`):**
   - Implement circuit breaker for transaction failure rates.
3. **Common:**
   - Migrate credential handling to a more secure mechanism (if supported by infra) or ensure strict runtime protection (e.g., clearing `process.env` after initialization if possible).
   - Add automated test cases for settlement failure modes.

## Decision Criteria
- Behavioral correctness verified with reproduction scripts.
- Circuit breaker trip/reset behavior logged and alerted.
- Zero regression in current functionality.
